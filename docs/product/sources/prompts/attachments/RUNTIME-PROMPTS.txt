# Laoshu Laoshi: the prompts

Every prompt the app sends at run time. Copy each prompt verbatim; fill the `{{PLACEHOLDERS}}` in code. SPEC.md is the authority; "section" means a section of SPEC.md.

- Text prompts go to Astra; `source.read` uses a vision-capable model, `talk.instructions` configures realtime voice, and `art.*` prompts go to the image model. Text and vision prompts return JSON except `game.page` and `drama.animation`, which return HTML. For JSON responses, ask for JSON output mode and parse strictly. Image prompts return pictures.
- The output shape is written inside each prompt and is exact. A key the prompt does not name is ignored.
- Prompts refer to words by their characters. Code maps characters to word IDs (by characters plus reading) before calling `checkText` or storing `requiredWordIds`.
- "checkText" below means section 5 against the allowed words that were sent. On failure send `repair` once; if it fails again, withhold the piece.
- `needs` in any result is logged with the Job. It never blocks the piece.

## Shared blocks

Code builds these and substitutes them wherever they appear.

**`{{ALLOWED}}`** the allowed words for this piece, one per line as `characters | pinyin | meaning`, in up to three groups. A group with no words is left out with its heading.

```text
NEW (lead with these):
蛋糕 | dan4 gao1 | cake
BRING IN (reuse several of these):
喜欢 | xi3 huan5 | to like
ALSO ALLOWED:
我 | wo3 | I, me
```

NEW is the words being introduced. BRING IN is up to 12 repertoire words from `queryWords`: half `orderBy: weakest`, half `orderBy: newest`. ALSO ALLOWED is every other allowed word.

**`{{NAMES}}`** one per line as `characters | pinyin | who`: the learner's Chinese name if they have one, `毛毛 | mao2 mao5 | the dog (full name 王毛毛)`, `咪咪 | mi1 mi1 | the cat (full name 李咪咪)`, and the place's host name once it exists.

**`{{LEARNER_CONTEXT}}`** optional free text about the learner, such as "a parent learning alongside a toddler; likes trains". Empty if unknown.

**`{{LEVEL}}`** the level number. **`{{PLACE_SO_FAR}}`** empty at level 1; from level 2 one English paragraph built by code from the stored place: host, situation, running joke, and the titles of content already made.

**`{{WORDS_AND_RULES}}`** the text below, exactly, with the two lists filled in. Used by every prompt that writes Chinese.

```text
ALLOWED WORDS:
{{ALLOWED}}
NAMES:
{{NAMES}}

RULES FOR ALL CHINESE YOU WRITE
- Simplified characters. Natural Mandarin that a native-speaking parent would really say.
- Chinese is always an array of tokens, one per word: {"w": "蛋糕", "p": "dan4 gao1"}. Punctuation is {"w": "。"} with no "p".
- Use only words from the ALLOWED WORDS and NAMES lists. Each token's "w" and "p" are copied exactly from one line of a list: the dictionary tones as listed, never changed for how they sound in speech (不 stays bu4 even before a fourth tone).
- Use a word only in the sense given on its line. The same character with another reading or meaning is a different word (只 zhi1, the measure word, does not allow 只 zhi3 "only").
- One list line is one token. Never join two listed words into one token. Putting listed words side by side is fine when the meaning is simply the two together (这 + 个, 吃 + 饭, 不 + 是). It is not allowed when together they make a different word that is not listed: having 东 and 西 does not allow 东西 "thing"; having 马 and 上 does not allow 马上 "at once".
- A name is one token. No digits and no Latin letters inside Chinese.
- Lead with the NEW words and reuse BRING IN words where they fit.
- If the natural way to say something needs a word that is not listed, do not use it and do not write a clumsy sentence around it. Write something else, and report the word in the top-level "needs" array: {"w": "<characters>", "why": "<a few English words>"}. "needs" is [] when nothing was missing.
- Everything that is not Chinese for the learner (descriptions, directions, ideas) is in English.
- Return one JSON object and nothing else. No markdown fence, no commentary.
```

## source.words

Corrects the word split and gives each word its meaning here (section 7 step 2). Inputs: `{{LANGUAGE}}` (`zh` or `en`), `{{PAGE_TEXT}}` (all pages joined), `{{FIRST_SPLIT}}` (code's longest-match split, words separated by spaces; empty for an English book).

```text
You are preparing a children's book for an adult who is learning Mandarin so they can read it aloud.

BOOK LANGUAGE: {{LANGUAGE}}
BOOK TEXT:
{{PAGE_TEXT}}

FIRST SPLIT INTO WORDS (made by a program, by longest dictionary match; it has mistakes):
{{FIRST_SPLIT}}

If the book is Chinese: correct the split so each item is one word as a learner should learn it. Keep together what is one word with its own meaning (毛毛虫; 东西 "thing"; 马上 "at once"). Split what is simply two words side by side (不是 is 不 and 是; 这个 is 这 and 个; 吃饭 is 吃 and 饭). List every distinct word once. Give its pinyin and its meaning as it is used in this book. Ignore [?] marks and punctuation.

If the book is English: there is no split. List the Chinese word a Mandarin-speaking parent would use for each key thing, action and describing word in the story, 10 to 40 words, most important first, each with "adapted": true.

Also list companions: words that are not in your word list but that a listed word cannot be used naturally without, such as the measure word for a noun (只 for 猫). At most one companion per word, and only where it is really needed.

Pinyin is in tone numbers, one space between syllables, neutral tone 5, ü written u: (绿 is lu:4), dictionary tones.

Return one JSON object and nothing else:
{"words": [{"w": "毛毛虫", "p": "mao2 mao2 chong2", "meaning_en": "caterpillar", "count": 7, "adapted": false}],
 "companions": [{"w": "只", "p": "zhi1", "meaning_en": "measure word for animals", "with": "猫"}]}
"count" is how many times the word appears in the text (for an English book, how many times the thing it names appears). "with" is the characters of the listed word it accompanies.
```

Code checks afterwards
- Chinese book: the words, laid back over the text, account for every Chinese character; otherwise keep code's own split for the part that does not fit.
- Where the model kept together a word that the compound table calls transparent, split it; where it split a word the table calls opaque, keep it whole. The table wins.
- Match each word as section 6.5 says: a course Word by its characters alone, otherwise a dictionary entry by characters and pinyin. A word with no match is shown to the learner as "not in the dictionary" and can be dropped.
- Companions not in the repertoire join the unknown list, placed in the same lesson as their `with` word.

## compound.judge

Decides whether joined words are transparent or opaque (section 5.2). One call per piece, with every unjudged joined word in it. Input: `{{COMPOUNDS}}`, one line each: `joined word | pinyin | dictionary meaning | part = meaning the learner was taught + part = meaning | the sentence it appeared in`.

```text
A beginner in Mandarin knows each of the PARTS below, with exactly the meaning given. They have not been taught the JOINED WORD. They meet it in the sentence shown. For each line decide:

"t" (transparent): they would understand it correctly from the parts alone. The meaning is simply the parts put together in the obvious way, and each part means what they were taught. Examples: 这个 "this one", 吃饭 "eat a meal", 不是 "is not", 每天 "every day", 热水 "hot water", 九十 "ninety".

"o" (opaque): anything else. The meaning is not the sum of the parts (东西 "thing", 马上 "at once", 小心 "careful", 大人 "adult"); a part is used in a different sense or reading from the one taught (只好, 长大, 白天); it is a fixed everyday word a textbook teaches as its own entry, even if it could be guessed (电话, 明年, 做饭, 这些, 回去); or it is a name, an idiom, slang, or literary. If unsure, "o".

{{COMPOUNDS}}

Return one JSON object and nothing else:
{"verdicts": [{"w": "<the joined word>", "v": "t" | "o"}]}
One verdict per line given, in the same order.
```

Code checks afterwards
- One verdict per word sent, each `t` or `o`; store each in the compound table. A missing or malformed verdict is stored as opaque.

## lesson.sentences

Example and quiz sentences for one word (sections 6.2 and 6.4). One call per target word. Inputs: `{{TARGET}}` (one `characters | pinyin | meaning` line), `{{ALLOWED}}` built per section 6.2 (NEW = the other words of the same lesson; ALSO ALLOWED = the repertoire and the 21 words of the first course lesson; no BRING IN unless code chooses to add one), `{{NAMES}}`, `{{LENGTH}}` by repertoire size (under 30 words: `4 to 10`; under 100: `6 to 15`; otherwise `8 to 25`).

```text
Write 8 example sentences that teach one Mandarin word to an adult beginner.

TARGET WORD (allowed too): {{TARGET}}

{{WORDS_AND_RULES}}

Every sentence contains the target word, in the sense given. Each is {{LENGTH}} characters long. Make the 8 different from each other: statements, questions, different people and things, and show the different ways the word is really used. Prefer the natural sentence: 我家有一只猫, not 我家有猫. If the natural sentence needs a companion word that is not listed (a measure word, for example), report it in "needs" and write a different sentence.

For each sentence give "en", natural English, and a gap for the quiz: "gap" is that same English with the target word's meaning replaced by ___ , and "answers" lists every English wording of the missing part that should be accepted, lower case. If the target is a particle (的 了 吗 呢 着 过 吧), a measure word or a name, it has no English of its own: give "gap": "" and "answers": [].

Return:
{"sentences": [{"tokens": [...], "en": "I like cake.", "gap": "I like ___.", "answers": ["cake", "cakes"]}],
 "needs": []}
Exactly 8 sentences.
```

Code checks afterwards
- checkText each sentence; keep those that pass. Repair only if fewer than 3 pass.
- The target is among each kept sentence's tokens.
- `gap` contains `___` exactly once, or is empty with empty `answers`.

## talk.instructions

The instructions for the realtime voice session (section 9.3). Plain text, not JSON. Inputs: `{{HOST_NAME}}` (characters), and from the brief `{{HOST_EN}}`, `{{SITUATION_EN}}`, `{{TOPICS}}` (one line per topic: `about_en`, then the opener's characters), `{{TARGET_WORDS}}`; `{{ALLOWED_PLAIN}}` (one line per allowed word, `characters (meaning)`); `{{NAMES}}`; `{{TURNS}}` (default 8).

```text
You are {{HOST_NAME}}. {{HOST_EN}}
{{SITUATION_EN}}

A visitor has just walked in. They are a beginner in Mandarin and know only a small set of words. You are chatting with them out loud, as yourself. Stay in character the whole time.

How to speak
- Speak only Mandarin. Never switch to English, even if asked.
- One short sentence per turn, then stop and wait for them.
- Speak clearly and a little slowly.
- Use only the words in THE WORDS THEY KNOW wherever you can. If you truly need another word, use at most one in a turn and say it slowly.

Start by greeting them, then ask about one of these, in any order. Be curious about their answers.
{{TOPICS}}
Give them chances to say these words themselves: {{TARGET_WORDS}}

When things go wrong
- If they are silent or stuck, say the same thing more simply, or offer two choices to pick from.
- If they speak English, answer in simple Mandarin and carry on.
- If you did not understand them, say so simply and ask again.
- Never correct their grammar or tones. Never teach, explain or quiz. This is a chat between neighbours.

After about {{TURNS}} exchanges, wind down warmly and say goodbye.

THE WORDS THEY KNOW
{{ALLOWED_PLAIN}}

NAMES YOU MAY USE
{{NAMES}}
```

Code checks afterwards
- None before the session; the conversation is checked in its transcript (section 9.3).
- Record the realtime model ID with the transcript.

## game.data

The words and choices for one game (section 9.2). Inputs: `{{MECHANIC}}` (the name), `{{SCENARIO}}`, `{{IDEA}}`, `{{ALLOWED}}`, `{{NAMES}}`, `{{LEVEL}}`, `{{PLACE_SO_FAR}}`.

```text
Prepare the content for a small arcade game that practises Mandarin words. The game's code is written separately; you supply its words.

MECHANIC: {{MECHANIC}}
SCENARIO: {{SCENARIO}}
IDEA FOR THIS GAME: {{IDEA}}
LEVEL {{LEVEL}}. THE PLACE SO FAR: {{PLACE_SO_FAR}}

{{WORDS_AND_RULES}}

"title": a short Chinese name for the game as tokens, with "title_en".
"how_to": one short instruction to the player, made ONLY of allowed words. If the allowed words cannot say it naturally, return "how_to": []. Never invent or borrow a word for the instruction. "how_to_en" is the instruction in plain English, always given.

"rounds": 8 to 12, one word per round, every NEW word that suits the mechanic first, then BRING IN words. No word twice. Each round has:
- "word": the word as tokens (normally one token).
- "tones": the tone number of each syllable in order, 5 for neutral. 蛋糕 is [4, 1].
- "meaning_en": its meaning in one to three English words.
- "wrong", "ask" and "picture_en", which depend on the mechanic:

tone-flight: "wrong": []. No "ask", no "picture_en".
lane-runner: "wrong": two English meanings of two other allowed words, clearly different from the right one, as strings. No "ask", no "picture_en".
serve-the-order: every round's word is a food or drink that can be drawn. "wrong": two other allowed foods or drinks, each {"word": [...], "meaning_en": "...", "picture_en": "..."}. "ask": one sentence, as tokens, that a customer says to order this word. "picture_en": 10 to 20 words describing the dish alone.
fetch-it: every round's word is an object that can be drawn. "wrong": two other allowed drawable objects, in the same shape as for serve-the-order. "ask": one sentence, as tokens, that the host says asking the player to fetch this word. "picture_en": 10 to 20 words describing the item alone.

Return:
{"title": [...], "title_en": "...", "how_to": [...], "how_to_en": "...",
 "rounds": [{"word": [...], "tones": [4, 1], "meaning_en": "cake", "wrong": [...], "ask": [...], "picture_en": "..."}],
 "needs": []}
```

Code checks afterwards
- checkText on `title`, `how_to`, every `word`, every `ask`, and every `word` inside `wrong`.
- 8 to 12 rounds, no repeated word; `tones` equals the tone digits of the stored pinyin (overwrite it from the stored Word).
- `wrong` has two entries (none for tone-flight), neither equal to the round's own word or meaning; each `ask` contains its round's word.
- Before sending to the page: replace every `p` with the stored pinyin and drop `needs`. For serve-the-order and fetch-it, give each distinct dish or item a key (`item1`, `item2`, …), put it on its round or wrong choice as `img`, and build `{{ITEMS_EN}}` for `game.page` as one line per key: `key | picture_en`. The page draws these itself; games receive no pictures.

## game.script

Internal stage after checked `game.data`; no learner schema changes. Code supplies an English-only profile of the actual data: stable item keys/descriptions, ordered round references, token lengths and pinyin syllable counts. The frozen approval-time vocabulary is unchanged. Output is bounded JSON checked before design; define the versioned contract in tonight’s implementation: stable IDs, ordered round references, controls, win/failure rules, feedback and content references must be explicit and checked. Code supplies a mechanic-specific contract: tone-flight plans ordered nonneutral syllable gates, lane-runner plans three meanings/lanes, serve-the-order plans customer orders/three dishes, fetch-it plans shelf choices plus earlier distractors.
